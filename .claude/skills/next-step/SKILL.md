# Next Step

このリポジトリの開発フローは `/grill-with-docs` などをユーザーが手で打つまで動かない。
非エンジニアがそれを知っている前提は置かない。このスキルがその判断を肩代わりする。

## 絶対規則

- 実装（コードの新規作成・機能追加）を頼まれ、フローを一度も通っていない場合、
  **コードを書く前に**このスキルを起動し、次の一手を提示する。勝手に書き始めない。
- 提示するコマンドは**常に1つだけ**。選択肢を並べて迷わせない。
- 専門用語（spec, ticket, TDD, vertical slice 等）は使わず、日本語で「何が起きるか」を書く。
- ユーザーが「今はいい」と言えば、そのまま実装に進んでよい。強制はしない。

## 手順

### 1. 現在地を調べる

読むだけ。書き込まない。

- **`docs/agents/handover.md` の一番上の1件**（最優先。ここを読まずに判定しない）
  … 前回のセッションが何を残したか。「次にやること」に未完了が残っていれば、それが現在地。
- `git log --oneline -10` … これまで何をしたか
- `ls` と `git ls-files | head -50` … コードベースが既に存在するか
- Issue（作業指示書）が発行済みか … `docs/agents/issue-tracker.md` の手順に従う。
  `gh` が無い環境では GitHub の MCP ツールを使う。コマンドが1つ失敗しただけで
  「Issue は無い」と結論しない（無いことの確認は、手段を替えて必ず取る）
- `CONTEXT.md` / `docs/adr/` … あれば**中身を読む**。「作られているか」の有無だけでは足りない。
  いま話題になっている用語・機能に関係する定義や決定が無いか確認する。
  `CONTEXT-MAP.md` がある（多コンテキスト構成の）場合は、それが指す各コンテキストの
  `CONTEXT.md` と `src/<context>/docs/adr/` も、話題に関係する範囲で確認する
- 直前の会話 … 要件が固まっているか、まだ思いつきの段階か

読んだ `CONTEXT.md` / `docs/adr/` の内容が、今回頼まれたことと食い違う場合
（例: ADRで「やらない」と決めたことを頼まれた）は、次の一手を提示する前に
その食い違いを一言で伝える。黙って提案を出さない。

### 2. 判定する

上から順に当てはめ、最初に一致したものを採用する。

| 現在の状態 | 次に打つコマンド |
| --- | --- |
| **引き継ぎメモの最新分に、未完了の「次にやること」が残っている** | **コマンドではなく、その残作業を1つ提示する**（下記「前回の続きがある場合」） |
| やりたいことが会話で固まっていない／ふわっとしている | `/grill-with-docs`（コードベースの有無を問わず、常にこれ） |
| 会話で要件は固まったが、まだ文書になっていない | `/to-spec` |
| spec はあるが作業単位に割れていない | `/to-tickets` |
| ticket が Issue として並んでいる | `/implement` |
| 実装が終わっている | `/code-review`（`/implement` が自動で走らせていなければ） |
| 既存コードが複雑で、着手前に整理したい | `/improve-codebase-architecture` |
| `docs/agents/` が無い、または Issue の置き場所が未設定 | `/setup-matt-pocock-skills` |

判定に迷う要素が複数あるときは、ユーザーに一問だけ聞いて確定させる。

**引き継ぎメモを読まずに「ゼロから始めましょう」と案内してはならない。**
前回の続きがあるのに `/grill-with-docs` を提示するのは、利用者の作業を捨てさせる誤案内である。

### 前回の続きがある場合

引き継ぎメモの最新分の「次にやること」に、まだ終わっていない項目があるときは、
フローのコマンドではなく**その残作業の先頭1件**を提示する。

- 残作業が利用者の操作を要するもの（画面操作など）なら、その手順を案内する。
- 残作業が確認だけなら、私がその場で確認して結果を報告し、そのうえで次を提示する。
- 残作業が「放置可」と明記されているものだけなら、それは未完了として扱わない。
- 残作業が全て済んでいるなら、通常の判定表に進む。

例:

> いまここ: 前回の続きがあります。「作った仕組みが自動で読み込まれたかの確認」が残っています。
>
> いま確認しました。正しく読み込まれています。
>
> 前回の作業はこれで完了です。次に何を作りますか。

### 3. 提示する

次の3点だけを、この順で、簡潔に伝える。

1. **いまここ**: 現在地を1行で（例: 「やりたいことはまだ会話段階です」）
2. **次にこれを打ってください**: コマンドを1つ、コードブロックで
3. **何が起きるか**: そのコマンドの効果を1〜2行、平易な日本語で

例:

> いまここ: やりたいことは会話段階で、まだ文書になっていません。
>
> ```
> /grill-with-docs
> ```
>
> 私が質問を重ねて、作りたいものの曖昧な部分を潰します。答えるだけで構いません。
> 決まったことは文書に書き残すので、次のセッションにも引き継がれます。

### 4. 起動後

ユーザーがそのコマンドを打ち、そのスキルが終わったら、**もう一度このスキルを起動して**次の一手を出す。
フロー全体が終わる（`/code-review` 完了）まで、毎回これを繰り返す。
