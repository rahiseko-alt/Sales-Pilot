# f — セッション終了の儀式

利用者は非エンジニア。「もう閉じていいのか」を自分では判断できない。
このスキルが確認を代行し、**根拠つきで終了可否を宣言する**。

宣言は嘘であってはならない。1項目でも満たせないなら「終了して問題ありません」と言わない。
**確認コマンドが失敗したことを「問題なし」と読み替えない。** 確認できなかったものは
「確認できませんでした」と書き、終了を認めない。

起動する場面と、一文字が別の意味に見えるときの扱いは
`docs/agents/flow-map.md`「セッションの開始と終了」が正。ここでは繰り返さない。

## 確認する4項目

上から順に片づける。**満たしていなければ、まず自分で満たしにいく。報告だけして終わらない。**

### 1. 手元の未保存の変更がゼロ

`git status --porcelain` の出力が空であること。
空でなければ、内容を確認したうえでコミットする。

### 2. 未送信の記録がゼロ

「この枝が、同じ名前で送信先に存在し、手元と一致している」ことを確認する。
`@{u}`（上流）に頼らない。枝を作った経緯によっては別の枝を指しており、
上流が未設定なら空ではなく**エラー**になるため、成否だけでは判定できない。

```sh
b=$(git rev-parse --abbrev-ref HEAD)
git fetch origin "$b" 2>/dev/null
git rev-parse --verify --quiet "refs/remotes/origin/$b" >/dev/null \
  && git log "origin/$b..HEAD" --oneline
```

- 2行目が何も出力しなければ、未送信はゼロ。
- 送信先に同名の枝が無い（3行目が偽）なら**未送信あり**。`git push -u origin "$b"` で送る。
- 出力があれば未送信あり。同じく送る。

### 3. 引き継ぎメモに今回の内容が記載済み

`docs/agents/handover.md` の一番上が、今回のセッションの内容になっていること。
なっていなければ、`docs/agents/flow-map.md`「引き継ぎメモ」の手順どおりに1件追記する
（書式・整理・コミット・1行報告まで、あの節が正）。

### 4. 提出中の変更の状態を明示

開いている提出物（PR）があるかを `docs/agents/issue-tracker.md` の手順で調べる。
`gh` が無い環境では GitHub の MCP ツールを使う（対応表は同ファイルの冒頭）。
**コマンドが1つ失敗したことを「提出物は無い」と読み替えない。**
手段を替えても確認できなければ、その旨を報告し、終了を認めない。

あれば、番号・題名・既存のものと衝突していないかを報告に載せる。

## 提出中の変更が残っている場合

終了は妨げない。ただし**明示したうえで、いま反映するかを一度だけ尋ねる**。

> 提出中の変更が1件あります（#12「〇〇の追加」／衝突なし）。
> 先にマージしますか。不要であればこのまま終了できます。

「する」と答えられたらマージし、結果を4項目の確認に反映する。
「不要」または答えを待たずに終了を求められた場合は、残っている旨を報告に明記して終了を認める。
**勝手にマージしない。**

## 満たせないとき

まず自分で解決を試みる（送信の再実行、衝突の解消など）。
それでも残る場合は **「終了できません」と明言**し、次を出す。

- 何が満たせていないか（項目名）
- なぜか（1〜2行、日常語で）
- どうすれば解決するか。利用者の操作が要るならその手順

「たぶん大丈夫」と言わない。

## 報告の形

全項目を満たしたときだけ、次の形で報告する。
（`flow-map.md`「説明の書き方」の3ブロックではなく、この型を使う。同節に明記された例外。）

> **セッションを終了して問題ありません。** この作業環境を破棄しても、失われるものはありません。
>
> 確認した項目:
> - 手元の未保存の変更: なし
> - 未送信の記録: なし
> - 引き継ぎメモ: 今回の内容を記録済み
> - 提出中の変更: なし（または「#12 が提出中のまま残っています」）
>
> 次回は「s」と打てば、続きから再開できます。

## 作業が何も無かった場合

雑談や質問だけで終わったセッションでは、引き継ぎメモを書かない。
中身の無い記録が溜まると、本当に必要な記録が押し出されるため。
この場合も1〜2は確認する。

> 記録すべき変更はありません。セッションを終了して問題ありません。
