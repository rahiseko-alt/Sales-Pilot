# 営業担当AI

企業ごとに案件の状態を保存し、候補発見 → 調査 → 改善提案 → 個別メール → 返信判断 → 人間への引き継ぎを継続するローカルアプリです。Python標準ライブラリのみで動作します。

## 起動

このフォルダで `python server.py` を実行し、http://127.0.0.1:8765 を開きます。Windowsでは `powershell -ExecutionPolicy Bypass -File start.ps1` でも起動できます。

画面のサンプル登録で架空企業を追加し、営業サイクルを実行してください。返信シミュレーションで「詳しい話を聞きたい」「配信停止してください」等を入れて、引き継ぎと停止を確認できます。サンプルは実在企業への営業ではありません。

## 担当業務

- 求人RSS/Atom、企業URL、手入力の営業リストから候補を蓄積。
- 公開ページの本文・URL・取得時刻を調査根拠として記録。
- 根拠をもとに課題を仮説化し、既存ツールや自動化の改善案、メールを作成。
- 案件とメールスレッドをSQLiteへ保存。再起動しても案件を継続。
- 専用AgentMail受信箱を接続すると送受信・返信を処理。
- 配信停止を抑止リストへ登録。商談希望・重要判断は人間へ渡す。

AIの標準接続は **Claude Codeのサブスクログイン** です。OpenAIのAPIキーは必須ではありません。Claude Code未ログイン・生成失敗時は、その旨を記録してルールによる提案に切り替えます。メールのシミュレーション設定はAIの接続方式とは別です。

## Claudeのサブスクで動かす

同じWindowsユーザーのターミナルで `claude auth login` を実行し、ClaudeのPro／Max等のアカウントへログインします。画面設定のAI接続を「Claude Code」にします。営業担当AIが `claude -p` を呼び出し、Claude Codeの認証を使って提案を生成します。OAuthトークンの取り出しやAPIへの転用は行いません。

ClaudeとClaude Codeで利用上限を共有します。別途有効にした追加使用量の設定はClaude側の設定に従います。[サブスク利用の公式案内](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)、[CLI自動実行の仕様](https://code.claude.com/docs/en/headless)。このPCでは2026年9月29日にサブスクログインと、架空資料からの実提案生成を確認済みです。

モデルは `.env` の `CLAUDE_MODEL=sonnet` で指定できます。ツール呼び出しを無効にし、公開資料を入力としてJSON提案のみを取得します。メール送受信はアプリが別途管理します。既存のルール生成済み案件はそのまま保存し、新しい案件から選んだAIを使います。

## 実運用の接続

1. 上の手順でClaude Codeにログインします。OpenAI互換APIを使いたい場合だけ、画面のAI接続をOpenAIへ変更し、`.env` に `OPENAI_API_KEY`・`OPENAI_MODEL` を設定します。
2. AgentMailで専用受信箱を用意し、`AGENTMAIL_API_KEY` と `AGENTMAIL_INBOX_ID` を設定します。キーは画面へ表示しません。
3. 送信者名と回答可能な料金体系、候補ソース、実際に確認した宛先を登録します。
4. `.env` の `SALES_ALLOW_LIVE_SEND=yes` を設定してサーバーを再起動し、画面設定のシミュレーションをオフにします。
5. 自動送信をオン、一時停止をオフにすると、個々のメール指示を待たずに営業を進めます。送信上限は1日1〜100通で設定できます。

画面上の「担当AIを実行」は継続稼働も開始します。ワーカーは30秒ごとに案件・受信を確認し、候補ソースの再探索は30分間隔です。停止は設定の「担当AIを一時停止」で行います。個別の実行ボタンは停止中でも指定した処理を実行します。

ai_replies=trueの現在のテスト運転では、Claudeが企業資料・提案・料金・会話履歴・最新返信を読み、回答か人間引き継ぎ等を判断します。配信停止や契約・クレーム等はアプリ側でも優先して停止します。AI生成失敗時は定型文を送らず、エラーを記録します。ai_replies=falseの場合だけ旧キーワード方式を使います。契約や価格交渉をLLMへ任せる実装ではありません。人間への通知は管理画面の引き継ぎ一覧・活動履歴で行い、Slackや外部通知サービスは未接続です。送信結果が不明な場合は `uncertain` として再送を止めるため、AgentMail側で結果を確認してください。実際のAPIキーを使ったLLM生成・AgentMail送受信は未検証です。

## Paperclip

営業案件の記憶は本アプリが保持します。Paperclipからは `paperclip_tick.py` を定期実行し、営業サイクルを起動できます。サーバーを先に起動し、processアダプターに次を設定します。

```json
{
  "adapterType": "process",
  "adapterConfig": {
    "command": "python",
    "args": ["paperclip_tick.py"],
    "cwd": "C:/Users/user/Documents/ChatGPT/New project/sales-agent",
    "timeoutSec": 300
  }
}
```

Paperclip自体のインストール、会社作成、エージェント登録はこの成果物に含めていません。設定例は接続用で、Paperclip上での実行は未検証です。processアダプターの設定はAPIまたは会社エクスポートから行う仕様です。[公式ドキュメント](https://docs.paperclip.ing/reference/adapters/process/)

メール送受信の実装仕様は[AgentMail公式ドキュメント](https://docs.agentmail.to/messages)を参照しています。

## 運用範囲

自動運転にはアプリのプロセスが起動している必要があります。PC停止中には動きません。公開Web全体を無制限に探索する検索エンジンは含めていません。RSS/Atomや対象URLを指定して営業候補を取り込みます。連絡先は推測せず、確認した宛先を登録してください。

求人タイトルから取得した候補は企業名・宛先の確認が必要です。課題と効果は仮説であり、数値効果や実績を確約しません。最終見積、契約、クレーム対応は人間が担当します。デモは説明用の簡易機能で、顧客の業務システムそのものではありません。

ローカル利用を前提とし、インターネットへ直接公開しないでください。実送信に使う営業対象、送信者情報、料金、送信件数は運用設定で決めてください。

## 検証

会社概要を補助資料として調査するには、設定画面の「会社概要の確認済みURL」に、1行ごとに `会社名 | URL` を登録します。企業ごとに最大2件まで、求人ページと重複するURLは一度だけ取得します。登録済み3社の例は `company-profile-sources.json`、人数の基準日と対象範囲は `docs/research/company-size-sources.md` にあります。

これは人が確認した企業とページの対応を利用する機能です。取得失敗は記録して他の資料の調査を続け、未登録先へのリダイレクトや部署・子会社込みの人数を会社単体の確定値にしません。新規調査から適用され、既存の送信済み案件を再送しません。

`python -m unittest discover -v` でテストを実行します。
