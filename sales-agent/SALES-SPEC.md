# 営業担当AIの仕様

元の構想と追加仕様メモを引き継ぐ。目標は見込み客発見から商談化まで案件状態を持つ営業担当AI。AgentMailは外部との共通窓口、内部のAI連携にメールは挟まない。

## 進め方

1. 設定
2. メールの往復
3. 一連の自動運転
4. 回答・提案品質
5. 日々の修正

現在ステップ3。ClaudeサブスクとAgentMailの接続、本人宛て送受信、自由文に対するClaude自動返信と本人の受信確認は完了。

## 今回の営業対象

Excel入力・転記・集計の求人がある企業。求人は人手負担のシグナルであり、実際の課題と削減効果はヒアリングで確認する。派遣先が匿名の募集を実在顧客として断定しない。

送信者情報は seller-profile.json に出典付きで保存する。公開されたAI業務改善支援の範囲を利用し、料金・納期・実績は作らない。

## 内部の4役

- 営業責任者：案件状態、次の行動、配信停止、引き継ぎ、実行履歴。
- リサーチ担当：求人シグナルと企業公開資料の取得、根拠・日時の保存。
- 提案・返信担当：Claudeによる個別提案、会話履歴を使う質問対応。
- 開発担当：必要に応じた簡易デモ作成。会社ごとの自動プロトタイプ生成は未実装。

現在の実装はアプリ内の処理モジュールで分業する。Paperclipへの4エージェント登録や独立した長期タスク管理は未実施。構想と実装済みの機能を混同しない。

## 検証と実送信

実企業の情報から提案を作るが、初回の検証メールも本人だけへ送る。案件ごとの delivery_overrides で検証先を指定し、企業の連絡先情報を書き換えない。返信はスレッドと確認済み送信先で案件へ対応づける。本人宛ての allowlist を維持する。

一連の処理が動いても、品質評価や本番営業の完了扱いにはしない。
