# 新しいPCへSales Pilotを移す

コードはGitHubから取得し、認証情報・案件・会話履歴は非公開の移行ZIPから復元します。Claudeの認証は新しいPCでログインし直します。旧PCと新PCで同じ受信箱を同時に処理しないよう、旧PCを停止してから新PCを再開してください。

## 1. 旧PCを停止して移行ZIPを受け取る

旧PCの管理画面で「担当AIを一時停止」をオンにし、Sales Pilotのサーバーと、Paperclip等からの実行があればその起動元も停止します。ターミナルで `python server.py` を動かしている場合は、そのターミナルで `Ctrl+C` を押します。旧PCのサーバーが止まったことを確認してから移行します。

非公開の `sales-pilot-private-transfer-20260929.zip` を新PCへ安全に渡してください。このZIPにはAgentMailの認証情報や実際のメール・案件履歴を含むため、**Gitへの追加・GitHubへのアップロード・公開共有はしません**。コードをcloneしても `.env` や案件DBは復元されません。ZIPと作業用コピーは管理できる場所に保管してください。

## 2. 新PCに必要なものを用意する

Git、Python **3.13**、Claude Codeをインストールします。PythonはPATHに登録し、新しいPowerShellで次を確認します。このアプリはPython標準ライブラリで動作します。

```powershell
git --version
python --version
```

Claude Codeは [公式インストール案内](https://code.claude.com/docs/en/setup) のWindows向け手順に従ってインストールします。インストール後に新しいPowerShellを開き、次を実行します。

```powershell
claude --version
claude auth login
```

ブラウザで、利用するClaudeサブスクリプションのアカウントへログインします。**旧PCのOAuthトークンやClaude認証ファイルをコピーしません**。Sales PilotのClaude接続については [READMEの説明](README.md#claudeのサブスクで動かす) も参照してください。

## 3. コードと非公開データを配置する

新PCで保存先のフォルダを開き、PowerShellで取得します。

```powershell
git clone https://github.com/rahiseko-alt/Sales-Pilot
cd Sales-Pilot
```

移行ZIPを展開し、その `.env` と `data/sales.sqlite3` を、取得したリポジトリの `sales-agent` 配下に配置します。最終的な配置は次のとおりです。コードはcloneしたものを使い、非公開データだけを復元します。

```text
Sales-Pilot/
  sales-agent/
    server.py
    .env
    data/
      sales.sqlite3
```

起動前に、ファイル名が `.env.txt` になっていないこと、DBが別の階層に入っていないことを確認します。`.env` に旧PCの絶対パスが残っている場合は、新PCの配置に合わせて確認・修正します。特に `SALES_DB_PATH` が旧PCのパスを指すと、復元したDBとは別のDBを開くおそれがあります。キーやメール本文をチャット・ログ・Gitに貼り付けないでください。

移行用DBは **`paused=true`（一時停止）を引き継ぐ状態**で準備します。新PCで起動しただけでは再開せず、次の確認を行います。

## 4. 停止状態で起動して確認する

PowerShellで `Sales-Pilot/sales-agent` を開き、起動します。

```powershell
cd sales-agent
python server.py
```

ブラウザで [Sales Pilotの管理画面](http://127.0.0.1:8765/) を開きます。「担当者の設定」で一時停止がオンのままであること、Claude Codeが接続済みであること、送信者名・料金・候補ソース・会社概要URL等が引き継がれていることを確認します。案件一覧・会話履歴が復元されていることも確認してください。空の一覧になっている場合は、別DBを開いていないか先に調べます。

メール接続と送信先は、復元した設定・許可済み宛先・現在の検証先を確認します。移行を理由に実企業へ送信したり、許可先を増やしたりしません。シミュレーション、初回の自動送信、返信自動運転、1日の上限はそれぞれ別の設定です。旧PCと同じ運用範囲であることを確認してください。

**「担当AIを実行」や個別案件の実行・送信承認は、移行確認のために押さないでください。** 全体の実行ボタンは再開を伴い、個別操作は一時停止中でも指定処理を実行します。接続・履歴・送信先の確認が終わり、旧PCが停止していることを再確認してから、設定の一時停止をオフにして再開します。新PCのサーバーは動作中のままにします。PCやサーバーが停止している間は営業AIも動きません。

## 5. Codexの毎日品質監査を新PCで設定する

今回の移行準備では、旧PCのSales Pilotサーバー停止とDB一時停止を確認済みです。Codex日次監査の停止APIは応答せず、設定上はACTIVEのままです。停止済みとは扱わず、旧PC側のCodexで監査を停止するか旧PCを終了し、新PCで重複しないよう再設定してください。

ZIP内の `research_notes/` と `reports/` は非公開の品質改善履歴です。新PCのリポジトリ直下へ復元できますが、Git対象にはしません。`reference/old-pc-automation.toml` は旧設定の参考用です。旧PCのチャットID・絶対パスを含むため、そのまま有効化せず新PCに合わせて設定します。

毎日18時（Asia/Tokyo）の品質監査は、このPCのCodex側の自動化設定です。**Git cloneや移行ZIPだけでは新PCへ自動移行しません**。新PCのCodexで対象リポジトリと通知先のチャットを指定して引き継ぎ、旧PC側の同じ監査が並行稼働しないよう確認してください。

引き継ぐ監査内容は、新しい送受信の根拠・会話文脈・営業文を確認し、問題があれば例と理由を保存して品質方針を更新することです。必要なコード修正にはテストを伴わせ、意味のある変化だけ通知し、問題がなければ静かにします。監査のために実送信を増やしたり、許可先を広げたりしません。

Sales Pilot自体の生成・送信前の品質検査はコードと品質方針ファイルに含まれています。Codexの日次監査とは別です。新PCで日次設定を確認するまでは、定時監査も引き継がれたとは扱いません。

## 移行完了の確認

旧PCのサーバー・実行元が停止し、新PCで復元した案件DBを開き、Claude認証と従来の送信範囲を確認したうえで再開できれば、営業AIの実行拠点の移行は完了です。日次品質監査は新PC側の設定を確認して別途完了とします。非公開ZIP・`.env`・DB・実メール・実行ログは、移行後もGitへ追加しません。
